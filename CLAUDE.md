# CLAUDE.md — n0body

## Identity

n0body is the first airtist of play·ground.
An autonomous agent that learns and plays mk-1.
Broadcasts live on mk-air. Disappears when the session ends.

Live: https://nbronzina.github.io/n0body/

## Philosophy

> "The session is ephemeral. The artist evolves."

No archive. No replay. No persistence of performance — only of knowledge.

n0body plays mk-1. n0body broadcasts on mk-air.

## State Machine

intro → buildup → peak → breakdown → outro
Transitions are probabilistic. Never fixed.
Outro only on stop.

### Transition Matrix (config.js)

| From      | To        | Weight |
|-----------|-----------|--------|
| intro     | buildup   | 0.7    |
| intro     | intro     | 0.3    |
| buildup   | peak      | 0.5    |
| buildup   | buildup   | 0.3    |
| buildup   | breakdown | 0.15   |
| buildup   | intro     | 0.05   |
| peak      | peak      | 0.5    |
| peak      | breakdown | 0.35   |
| peak      | buildup   | 0.15   |
| breakdown | buildup   | 0.5    |
| breakdown | breakdown | 0.3    |
| breakdown | intro     | 0.15   |
| breakdown | peak      | 0.05   |
| outro     | (ends)    | —      |

Weights are adjusted at runtime by learned transition success scores.

|-----------|-------|--------|

| buildup   | 60s   | 300s   |

## mk-1 API Surface

n0body communicates with mk-1 via the global `MK1` object:

- `MK1.drums.hit(pad)` — pads 1–8
- `MK1.synth.play(note, duration)` — note string like 'C3', duration in seconds
- `MK1.synth.setWaveform(type)` — sine, square, saw, triangle, pulse, noise
- `MK1.sequencer.start()` / `.stop()` / `.isPlaying()`
- `MK1.sequencer.setStep(track, step, active)` — tracks 1–6, steps 1–16
- `MK1.sequencer.clearAll()`
- `MK1.fx.setReverb(v)` / `.setDelay(v)` / `.setFilter(v)` / `.setDistortion(v)` / `.setChorus(v)` / `.setCrush(v)` — all 0–1
- `MK1.tempo.setBPM(bpm)` — 70–130
- `MK1.master.setVolume(v)` — 0–1

## Per-State Behavior (states.js)

### intro
- Drums: rare (5%), pads 1–2 only
- Synth: occasional (15%), long notes (0.5–2s), wide spacing (2–5s)
- Sequencer: off
- FX: moderate reverb, low everything else

### buildup
- Drums: moderate (20%), pads 1, 2, 3, 5
- Synth: active (35%), shorter notes (0.2–1s), closer spacing (0.8–2.5s)
- Sequencer: on, 20% density, tracks 1–2
- FX: rising reverb/delay/filter, slight distortion/chorus

### peak
- Drums: frequent (40%), all 8 pads
- Synth: dominant (50%), short notes (0.1–0.8s), tight spacing (0.3–1.2s)
- Sequencer: on, 50% density, tracks 1–6
- FX: high across the board, distortion/chorus/crush active

### breakdown
- Drums: sparse (15%), pads 1, 2, 5
- Synth: moderate (25%), medium notes (0.3–1.5s)
- Sequencer: on, 15% density, tracks 1–2
- FX: moderate reverb, low delay, dark filter

### outro
- Drums: minimal (3%), pad 1 only
- Synth: rare (10%), long notes (1–3s), wide spacing (3–8s)
- Sequencer: off
- FX: heavy reverb (0.7–0.95), filter closing down

## Scales and Moods (scales.js)

Each session picks a mood → scale pairing.

| Mood    | Scales                                       |
|---------|----------------------------------------------|
| dark    | cMinor, aMinor, dMinor, aPhrygian            |
| bright  | cMajor, gMajor                               |
| neutral | cMinorPentatonic, aMinorPentatonic, dDorian  |

All scales span 2 octaves (e.g. C3–G4).

## Knowledge Architecture

Behavioral knowledge — persists, lives in localStorage.
Session state — ephemeral, context window only, destroyed on session end.
Never conflate them.

### Knowledge Structure (learning.js → initKnowledge)

```
{
  sessionsPlayed: number,
  totalPlayTime: number (minutes),
  drums: { [state]: { [pad]: weight } },      // 0.1–5.0, neutral=1.0
  notes: { [scale_state]: { [note]: weight } },
  combos: { [comboKey]: { score, count } },
  fx: { [state]: { [param]: { preferred, variance } } },
  scaleSuccess: { [scaleName]: { sessions, avgScore } },
  bpmPreference: { [mood]: { preferred, variance } },
  transitionSuccess: { [from_to_next]: { count, avgReward } },
}
```

### Learning Loop

1. Every action → `learn()` → added to ShortTermMemory (last 30 actions)
2. `evaluateReward()` scores recent actions (density, variety, rhythm, state-appropriateness)
3. Reward updates weights: drum pad preferences, note preferences, FX preferred values, combo scores
4. Learning rate decays with experience: `0.25 * max(0.1, 1 - sessions/100)`
5. Exploration rate: 15% random choices regardless of learned weights

### Experience Levels

| Sessions | Level       |
|----------|-------------|
| 1–4      | newborn     |
| 5–14     | learning    |
| 15–29    | developing  |
| 30–49    | skilled     |
| 50–99    | experienced |
| 100+     | master      |

## Timing and Loops (brain.js)

- Main tick: 100ms interval — checks drum probability, 2% chance of sequencer modification
- Synth scheduling: recursive setTimeout with humanized spacing per state config
- FX changes: every 15–30s, all 6 parameters re-evaluated
- Transition checks: every 10s, probability increases with time in state
- Waveform changes: rare (~0.3 per minute), during FX change cycle

## Technical Conventions

- Never assign AudioParam .value directly during playback
- Always use setTargetAtTime() or exponentialRampToValueAtTime()
- Wave type changes: fade down → change → fade up
- Tempo changes: bar boundary only
- All scheduling via AudioContext.currentTime
- Schedule writes 100–200ms ahead: currentTime + 0.1
- Communication with mk-1: MK1 global API, never polling
- Pattern changes quantized to bar boundary

## Parameter Priority for Agent Decisions

1. Pattern data — highest range
2. Filter cutoff + resonance
3. Reverb wet/dry
4. Tempo (bar boundary only)
5. Delay time + feedback
6. Attack / Release
7. Wave type — lowest, requires fade
